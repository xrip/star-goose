# План C-порта и правила сохранения поведения

## Две разные цели

Для ASM цель — тождественные53 684 байта. Для C-порта на другой платформе цель — эквивалентные состояния игры и изображения на выбранных контрольных входах, **не тот же EXE**. Современный C-компилятор не обязан повторять кодировки DOS-программы. Сначала сохраняем реальную семантику, потом отдельно улучшаем код и меняем поведение.

## Предлагаемая граница модулей

`game` владеет циклом, режимами и переходами. `entities` — стабильным массивом48 слотов, порядком обновления и таблицей handlers. `world` — декодированными картами, масками доступности и `sample_terrain`. `player` и `behaviors` — физикой и игровыми автоматами. `render` — индексированными пикселями, спрайтами и картой; `tunnel_render` — эталонной целочисленной геометрией. `hud`, `scores`, `sound_sequencer` остаются отдельно. `platform` предоставляет клавиатуру, чтение файлов, показ кадра и аудиовывод.

Не переносить всю игру как `AX/BX/DS[]` в тысяче строк C. Регистровый транскрипт бывает полезен как временный проверочный эталон отдельной функции, но конечный интерфейс должен описывать состояние и смысл данных. Не вводить универсальные vx/vy/health всем сущностям: у оригинала таких обязательных полей нет.

## Первый вертикальный срез

Сначала проверить загрузку файлов и FrameSet, затем вывести INTRO и отдельные кадры с правильной прозрачностью. После этого — RLE→карта→фон, Entity pool, culling и `render_entities`. Следующий срез — движение игрока/камера/sample_terrain без врагов. Потом подключать handlers небольшими группами, порядок спавна, HUD/счёт и сохранение. Туннель и звук подключать после появления стабильных тестовых снимков базовой игры.

`port/goose_model.h` — небольшой начальный набор типов/помощников: сериализация Entity, пул и применение кадра. `port/goose_model.c` не является игрой или полной заменой ASM. Добавленные проверки границ относятся к host API; совпадение с оригиналом предполагается на корректных входах. Их unit-тесты не доказывают эквивалентность всех процедур.

## Арифметика, которую нельзя «упростить»

| Оригинал | Требование при переносе |
|---|---|
| `ADD AL`, `INC byte` | Сначала wrap modulo256; только затем signed/unsigned проверка. |
| `ADD AX`, `NEG word` | Wrap modulo65536, где это реально используется; не signed-overflow UB. |
| `CBW` | Явное расширение знака8→16; значение `0xFF` становится−1. |
| `SAR` | Округление вниз для отрицательных значений, не деление C с округлением к0. |
| `JNS/JS` после byte-op | Проверяется бит7 результата именно этой8-битной операции. |
| `JA/JBE` и `JG/JLE` | Разные unsigned/signed отношения; тип `int` не заменяет выбор автоматически. |
| `LOOP` | Сначала декремент16-битногоCX; при начальном0 — не ноль итераций. |
| `DIV r8` | AX делится на8-битный делитель, quotient AL/remainder AH; выход за255 — особая ошибка CPU. |
| `REP` / direction flag | Учитывать DF и сохранение/изменение сегментов. |
| записьBYTE в WORD | Не обнулять старший байт без отдельного доказательства. |

Для всех структур сериализации нужны явные little-endian load/store. Host `sizeof(GooseEntity)` не обязан равняться23; не накладывать обычную C-структуру непосредственно на EXE. Переменные фиксированной ширины и проверки диапазонов удобнее, чем надежда на конкретное поведение компилятора.

### Боковое движение игрока — псевдокод

Для входного v в[-24,24]:

```c
if (left) {
    --v;
    if (v > 4) v = 4;
    if (v < -24) v = -24;
} else if (right) {
    ++v;
    if (v < -4) v = -4;
    if (v > 24) v = 24;
} else {
    v += (v < 0) - (v > 0);
}
x += floor_div_pow2(v + 3, 2);
if (x < 20) { x = 20; v = 0; }
if (x > 236) { x = 236; v = 0; }
```

Это лишь часть `update_player`: вызовы скорости/камеры идут до неё, рельеф, урон и оружие — после. Псевдокод не разрешает переносить эти фазы в произвольный порядок.

### Пул и диспетчер

```text
allocate(template):
    first slot whose flags.RENDER == 0:
        copy all 23 logical bytes
        return slot
    return failure

clear():
    every slot: flags = 0     // NOT memset the entire pool

update():
    snapshot current mode
    for slots in original order:
        process respawn/mode transition before slot
        when transition rebuilds world: restart pass
        if slot.UPDATE and handler_id != 0:
            invoke handlers[handler_id - 1](slot)
```

В исходнике dispatcher сохраняет SI вокруг вызова, но остальные регистровые побочные эффекты разных helper могут быть частью ABI. Перед переводом конкретной процедуры проверять все callers и таблицу35 входов, а не только тело до первого RET.

## Стек и дополнительные входы

`blit_sprite`: BP+4height,+6width,+8y,+10x, `RET8`; процедура меняет копии некоторых аргументов на стеке. `sample_terrain`: BP+4y,+6x, четыре локальных слова, `RET4`. `draw_tunnel_line`: BP+4y2,+6x2,+8y1,+10x1, `RET8`. Его helper `plot_tunnel_line_start` **наследует BP**, поэтому собственная C-сигнатура выводится из логического контекста, а не из близлежащего CALL.

Общие хвосты, fall-through и адресные входы отмечены в каталоге. При переносе их можно сделать private helper или объединить в одну функцию только после восстановления владения локальными данными и побочных эффектов.

## Рендер: сохранить до замены backend

Сначала работать с индексами цветов0..15, не цветами RGB. Source sprite stride160, packed high nibble first, per-sprite transparent index. EGA draw stride40, map stride32. `blit_sprite` обрабатывает `width>>1` пар; горизонтальная граница прижимает весь спрайт, а не выполняет обычное clipping. Y и высота обрезаются иначе, источник смещается на160 байт за отброшенную строку.

Стандартная библиотечная линия может отличаться по граничным пикселям. Для туннеля сначала перенести свой rasterizer со строгим `>` и включёнными концами; после проверки его можно заменить, но это уже отдельное изменение поведения. Битовые EGA регистры в ASM описывают режим чтения/latches, а не просто `dest &= color` над обычным RGB-массивом.

## Проверочная стратегия

Зафиксировать входы управления по игровым кадрам и отдельно моменты audio IRQ. На каждом кадре сериализовать48 записей, camera_y, player velocities, режим, счёт/ресурсы, маски карты и байтовые счётчики. Отдельно сравнивать256×160 индексированных пикселей и последовательность speaker divisor/duration.

Снимки нужно получить из настоящего запуска оригинала или корректного DOS-эмулятора. В этой работе полного запуска и такой трассы нет. Поэтому начальные C-модели и статические контракты не выдаются за готовый доказанно эквивалентный порт.

Обязательные сценарии: пул заполнен; слот свободен при UPDATE=1; spawn в ранний/поздний слот; переход y1023→0; смена направления при v±4/±24; оба направления нажаты; отсутствие топлива; смерть в момент перехода; быстрые press/release боковых устройств; полный rollover счёта; имя из12 символов; вход/выход туннеля; музыка одновременно с запросом эффекта.

Оптимизацию, новый таймстеп, динамический контейнер сущностей, исправление подозрительных мест и изменение управления выполнять **после** появления эталонных тестов, отдельными коммитами.
